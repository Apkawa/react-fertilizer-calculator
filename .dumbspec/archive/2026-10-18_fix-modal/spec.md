# 2026-10-18_fix-modal: поправка модального окна

**Created:** 2026-10-18T13:31:50+03:00

## Scope

В scope:
- Исправить общий компонент модалки `packages/ui/src/Modal` (`index.tsx` + `style.module.css`):
  1. **Центрирование:** модалка выровнена четко по центру экрана (и по горизонтали, и по вертикали).
  2. **Ширина по контенту:** контент модалки не растягивается на её ширину; ширина карточки определяется естественной шириной контента (с текущим `padding: 8px` карточки).
  3. **Ограничение вьюпортом:** карточка не шире и не выше вьюпорта (с отступом от краёв); при нехватке места — внутренний скролл карточки (`overflow: auto`).
- Обновить/добавить тесты, фиксирующие новое поведение (jsdom — структура; браузерный — геометрия: центрирование + ширина по контенту).

Out of scope:
- Поведение закрытия (backdrop/Esc/кнопка «Закрыть»), focus-management, a11y-атрибуты — остаются как есть.
- Внешний вид (фон оверлея, тень, цвета) — не меняется, кроме того, что необходимо для центрирования/размеров.
- Конкретные модалки приложения (Recipe/Mixer/FertilizerManager) — они не передают размеров, менять их не нужно.
- Новый prop размера (width/size) в API модалки — не вводить (KISS/YAGNI).

## Approach

1. **Оверлей:** `position: absolute` + inline `top: window.pageYOffset` заменить на `position: fixed; inset: 0` — оверлей всегда покрывает вьюпорт, хак со скролл-офсетом и нестилизированный `#modal-root` как позиционная база уходят (fixed не зависит от родителя). Inline-стиль `top` убрать из `index.tsx`.
2. **Центрирование:** добавить на оверлей `display: flex; align-items: center; justify-content: center` (текущие `justify-content`/`align-items` — dead code, без `display: flex` они не работают — причина «сдвинутости» на скриншоте). Оверлею добавить `padding` (например, 16px), чтобы карточка не упиралась в края вьюпорта.
3. **Ширина по контенту:** у `.modalCard` убрать `width: 80%` → `width: auto`; добавить `max-width: 100%` (относительно области оверлея с учётом его padding) — карточка сжимается под контент, но не шире вьюпорта. `max-height: 100%` + `overflow: auto` дают внутренний скролл при нехватке высоты.
4. **Мобильные media-запросы:** текущие (≤500px: `align-items: initial`, `width: 100%`) стали не нужны — new-подход покрывает все размеры; удалить.
5. **Тесты (TDD):**
   - jsdom `test.tsx`: текущие assertions не трогаем (про структуру/a11y/focus — не ломаются); layout в jsdom не меряется.
   - `browser.test.tsx` (chromium, local): добавить проверки геометрии — (а) диалог отцентрирован относительно вьюпорта (центр bounding box ≈ центр вьюпорта), (б) ширина карточка = естественная ширина контента, а не 80% вьюпорта (контент короче 80% → карточка уже 80% вьюпорта).
6. Итог: `pnpm full-check` (jsdom-тесты, lint, type, build) + локально `pnpm -C packages/ui test:browser` для геометрии.

## Constraints

- React 16, TS strict, Vite; `packages/ui` — source package, CSS modules (`style.module.css`) для Modal.
- Стек и структура компонента (portal в `#modal-root`, Helmet-style, render-props `button`/`container`) не меняются.
- Существующие jsdom/браузерные тесты и Storybook-стори должны продолжать работать.
- Husky pre-commit: `pnpm full-check` (test + lint + type + build) обязателен для коммита.
- Браузерные тесты (`test:browser`) — local/manual, не в CI; jsdom — в `pnpm test`.
- Решение пользователя: модалка ограничена вьюпортом с внутренней прокруткой.
