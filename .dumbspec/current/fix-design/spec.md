# fix-design — спецификация

## Контекст

После глобального рефакторинга UI — переезд на Tailwind v4, выпиливание
`theme-ui`/`rebass`/`styled-components` (ветка `v18-ui`, коммиты
`2ebe40e` … `cd27bd9`) — всё стало выглядеть «пососно» и возник ряд багов.
Задача: вернуть приложению корректный вид, починив 7 конкретных дефектов.

## Корневые причины (по research)

- **Глобальный баг порядка CSS-слоёв** — vanilla-extract блок
  `@layer components` эммитится в начале бандла, до декларация
  `@layer theme, base, components, utilities;`, и сама декларация не
  доживает до финального минифицирования → эффективный порядок
  `components < base` → **preflight перебивает стили атомов**
  (срезаны padding/border/bg/color у button/input и др.).
  Корень проблем 1, 2 и вертикального схлопывания 5.
- **П.3** — при миграции `<Flex>` превратился в голый `<div>` без `flex`
  (макро-ряд в «Настройка профиля»).
- **П.4** — потеряно legacy `sx={{position:"relative"}}`: скрытый
  `input[type=file]` разрешается относительно **вьюпорта** и закрывает
  кнопку-меню сайдбара.
- **П.6** — preflight срезал browser-default стили `ul` (отступы 40px,
  маркеры, margins); кастомных стилей дерева нет вообще.
- **П.7** — палитра тёмной темы в порядке (совпадает с legacy polaris),
  сломано другое: ни `body`, ни текст по умолчанию не привязаны к
  CSS-переменным → обычный текст чёрный в обеих темах, фон страницы
  никогда не темнеет; поверх тёмно-синих кард (#000639) чёрный текст
  ≈ нечитабельно. Плюс жёстко заданные `#fff`-поверхности (модалка,
  сайдбар, нав-табы).

## Подход (по пунктам)

1. **Кнопки** — починить порядок слоёв в бандле, чтобы декларация слоёв
   tailwind шла первой и минификатор расставил блоки
   `theme < base < components < utilities` → preflight снова ниже
   атомов, `buttonClass` вернёт себе фон/падинг.
2. **Инпуты** — тем же фиксом: `inputClass` вернёт border/padding/цвет.
3. **Профиль** — вернуть `flex` на макро-ряд в `RecipeTuneForm`.
4. **Скрытый input** — сделать кнопку импорта containing block
   (`position: relative` на button в трёх сайтах из `ImportExport`),
   чтобы `top:0;left:0` входил на кнопку, а не вьюпорт.
5. **Дропдаун** — покрывается фиксом слоёв: `inputClass` (padding 8 +
   border) вернёт строку триггера её ~3rem-высоту, `dropdownItemClass`
   — паддинг элементов списка. Контроль визуально.
6. **Дерево ссылок** — вернуть вид дерева: поуровневые отступы
   (padding-inline) + disc-маркеры для markdown-дерева в Справке;
   для дерева «Справка» в сайдбаре — отступы (маркеры по-прежнему
   отключены правилом `.react-router-tabs ul`). Hit-area ссылок
   NavTab сохранить.
7. **Тёмная тема** — `body`: background-color + color из CSS-переменных
   темы (страница темнеет, обычный текст = `--color-text`); жёстко
   заданные `#fff`-поверхности (кард модалки, кард сайдбара,
   `.nav-tab`) перевести на переменные темы, чтобы тёмная тема была
   единообразно тёмной и читаемой. Декоративное (forkMe-лента,
   element-чипы с `ELEMENT_BG`) не трогаем.

## Решения (пользователь, на гейте)

- **Scope**: 7 пунктов из draft — полный список. Новые замечания (если
  появятся) — в отдельную задачу.
- **Ориентир «правильного вида»**: привязок к состоянию до
  рефакторинга нет — достаточно, что «выглядит нормально»: кнопка
  похожа на кнопку, инпут отличим от текста, дерево — на дерево, тёмная
  тема читаемая.

## Открытые вопросы — решены (автономно)

- **Тёмная тема: контраст или переменные?** Переменные в порядке
  (dark-палитра = legacy polaris: 5 override). Сломан контраст:
  body-текст/фон не привязаны к переменным + кард без цвета текста +
  `#fff`-поверхности. Фикс по подходу п.7.
- **П.4 «затеняет»**: механизм — невидимый (opacity 0) input поверх
  кнопки: клики крадёт, hover-фидбек кнопки не работает. Фикс —
  containing block (п.4).

## Вне scope (зафиксировано)

- `pages/App` — CRA-остатки (`#282c34`): мёртвая страница, ни один
  `Route` на неё не указывает. Не чиним.
- `<meta name="theme-color" content="#000">`, forkMe-лента
  (`#000/#fff/#c11`), element-чипы с hex-фонами `ELEMENT_BG` +
  `text-black` — читаемы в обеих темах, не трогаем.
- Новые визуальные замечания за 7 пунктов — отдельная задача.

## Критерий приёмки

- Все 7 пунктов ведут себя корректно в светлой и тёмной теме
  (визуальная проверка playwright'ом: калькулятор, справка, плотность,
  пример).
- В собранном CSS порядок слоёв `theme < base < components < utilities`
  (preflight не перебивает атомы).
- `pnpm full-check` (test + lint + type + build) зелёный.
